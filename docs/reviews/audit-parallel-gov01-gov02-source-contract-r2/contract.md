### 4.1 Inputs and four pure exports

parseDevLogSource(envelope) and parseRoadmapSource(envelope) each return one FileResult for the supplied entry, including invalid/unreadable inputs; they never return null. collectSourceCoverage(domain, corpus_id, source_ref, entries, discovery) calls the appropriate pure parser and returns CorpusResult. relateSourceRecords(devCorpus, roadmapCorpus, productLines) returns AssociationResult. All inputs are immutable; no filesystem, Git, network, HTML evaluation or write exists inside these exports.

Envelope = {corpus_id:string, domain:"dev_log"|"roadmap", source_ref:string, entry_index:nonnegative integer, path:string|null, read:ReadInput}. The collector validates domain, identity and lexical repo-relative path (no absolute path, empty member, dot/dotdot or NUL) before access, assigns each enumerated source entry an ordinal, and preserves the enumeration receipt. source_ref is a full Git commit or an explicitly labelled capture ID. corpus_id uniquely binds the entire immutable ordered input inventory, capture identity and directory receipt; production caller supplies its SHA-256 identity. Fixture corpus IDs beginning "fixture:" are explicitly synthetic. Entries are sorted by raw UTF-8 path bytes, then original enumeration ordinal for repeated entries. Duplicates are preserved with their distinct ordinals; no lookup keyed only by path may replace an entry.

ReadInput is a finite tagged union:
- {kind:"captured", bytes:Uint8Array, supplied_sha256:string|null}; copy bytes before processing. Empty Uint8Array is a real read of an empty file.
- {kind:"unreadable", code:string, message:string, supplied_sha256:string|null}; no bytes were obtained. An ENOENT racing a successful directory enumeration is still an unreadable discovered entry, never an empty file or silently absent source.
- An invalid argument of any other shape produces invalid_input. Preserve any safely accessible actual Uint8Array as captured bytes; otherwise record unavailable reason "invalid_input_no_bytes". Do not invoke arbitrary getters, coerce attacker objects with String(), or serialize cyclic input. supplied_input = {type:string, invalid_fields:string[]} is an inert diagnostic summary, not a purported source.

This API intentionally does NO repository existence resolution. ReferenceValue.resolution is always "not_checked"; missing a path from the bounded dev_log/roadmap corpus never means "nonexistent". Source/Depends On syntax extraction remains pure and preserves raw cells. A future existence resolver would require a separately reviewed, explicit immutable inventory interface and new scope; no hidden existsSync/network call is admitted.

### 4.2 Exact FileResult and read-result union

FileResult = {schema_version:1, corpus_id, id, domain, source_ref, entry_index, path, outcome, bytes, raw_source, supplied_input, disposition, parts:Part[], blocks:BlockResult[], diagnostics:Diagnostic[], coverage:{blocks:Coverage,atoms:Coverage}}. path is null only for invalid input without a valid path. supplied_input is null except invalid_input. disposition is "parsed" or "unparsed", independent of a successful read. A valid text file with no Status is read_text and unparsed.

outcome is exactly "read_text" | "invalid_utf8" | "hash_mismatch" | "unreadable" | "invalid_input". Validation priority: envelope/read-shape validity, then supplied hash syntax/value, then strict UTF-8 decode, then source interpretation. For malformed supplied-hash syntax use invalid_input/E_INPUT with captured bytes; for a well-formed unequal digest use hash_mismatch/E_HASH. No decoding or grammar claim follows a hash mismatch. For unreadable input validate envelope/hash syntax, retain supplied hash as an untrusted claim, and return unreadable/E_FILE_READ. An unexpected host programming exception aborts the caller's operation with a failed receipt; it must not fabricate an empty CorpusResult.

CapturedBytes = {kind:"captured", base64:string, byte_length:integer, supplied_sha256:string|null, computed_sha256:64hex, hash_match:boolean|null}. base64 is the exact copied bytes, including invalid UTF-8, BOM and CRLF; computed_sha256 is computed solely from these bytes. hash_match=null means no supplied hash; false occurs only with hash_mismatch (or invalid hash syntax recorded as invalid_input with null match). Keep supplied and computed identities distinct. This contract chooses an inline exact byte payload, so a hash alone or an inaccessible reference is insufficient. A future external immutable byte reference is not implied by this schema.

UnavailableBytes = {kind:"unavailable", base64:null, byte_length:null, supplied_sha256:string|null, computed_sha256:null, hash_match:null, reason:"read_failed"|"invalid_input_no_bytes", read_error:{code:string,message:string}|null}. Do not use an empty digest, empty byte array, span [0,0), or raw_source="" for unavailable bytes. raw_source=null for all unavailable, invalid UTF-8, hash mismatch and invalid-input outcomes; read_text stores the exact strict-decoded source, retaining U+FEFF (decoder must not discard BOM). Empty successfully read text has raw_source="", captured byte_length=0 and the SHA-256 of empty bytes, plus I_EMPTY_FILE and an unparsed synthetic block.

For captured invalid_utf8/hash_mismatch/invalid_input, one error Part covers [0,byte_length); one file_error block contains one unparsed synthetic atom and one ErrorRecord. Lines are null because text interpretation was not admitted. For unavailable bytes, parts=[] and that block/atom/record all have span=null and raw_base64=null/raw_text=null; identity/error conservation remains mandatory. This is an explicit bytes-unavailable result, not an exception to retaining a discovered entry. No valid source input at all is invalid_input, not I_EMPTY_FILE.

### 4.3 IDs, spans, parts and exact graph endpoints

All IDs below are local to corpus_id. A cross-corpus reference is exactly {corpus_id,id}; no naked local ID is compared across captures. Domain is encoded in the file ID. File id = "dev_log/f" + entry_index or "roadmap/f" + entry_index; it resolves to the full provenance tuple (corpus_id,domain,source_ref,path,entry_index) in that FileResult. Corpus ID changes when any inventory/source/read receipt changes. Within a file, IDs are append-only source-order positions: part "/pN", block "/bN", atom "/aN" beneath block, field "/kN" beneath atom, cell "/cN" beneath atom, record "/rN" beneath block. Numbering starts at zero; blocks sort by start byte then recognition precedence in §5; atoms sort by start byte then source occurrence order; cells retain lexical column order. A synthetic block is b0 if it is the only block. Diagnostic id = owner_id + "/d/" + code + "/" + same-code occurrence index, assigned in source order (cross-record pairs sorted by qualified ID). Owners are file/block/atom/record, or "directory/N" in CorpusResult. ErrorRecord IDs use the normal block /rN namespace; they cannot masquerade as valid DevRecord/RoadmapRecord.

Span = {start_byte,end_byte,start_line,end_line}; byte offsets are half-open. For admitted UTF-8 text, line numbers are one-based, CRLF is one line terminator, LF and lone CR are one each. For a nonempty span end_line identifies the last occupied source line, not the next empty line after its final newline. A zero-width captured-text span has the insertion-point line (empty file line 1). For nondecoded captured bytes both lines are null; for unavailable bytes the whole span is null. Fields/cells use exact lexical substring spans, including spaces/wrappers, while value_text trims and removes only recognized balanced wrappers. Header/BOM/context bytes still belong to parts and cannot disappear through normalization.

Part = {id,kind:"context"|"candidate"|"error",reason:string|null,span:Span,raw_base64:string,raw_text:string|null,block_id:string|null}. Parts are ordered, disjoint, exhaustive over captured bytes. Concatenating decoded base64 parts yields exactly bytes.base64, even for nontext. Empty captured files have one zero-width context part; unavailable files have zero parts with explicit unavailable reason. context reasons include bom, prose, fenced_code, blockquote, whitespace and empty_file. candidate parts point to their block; error parts point to file_error blocks. A candidate block is a contiguous source interval including structural headers/separators/blank lines; source context never duplicates a candidate byte interval. All raw text/base64 inside nested atoms/records is an inspectable slice, not an additional member of the part partition.

BlockResult = {id,format:"table"|"bullet"|"plain"|"heading"|"unrecognized"|"file_error"|"empty",span:Span|null,raw_base64:string|null,raw_text:string|null,heading_context:Heading[],structural_spans:Span[],disposition,atoms:Atom[],records:Record[],diagnostic_ids:string[],coverage:Coverage}. Heading = {raw_title:string,span:Span}; enclosing headings are context unless they are themselves Status candidates. Each discovered block has at least one atom and record; empty/non-manifest/no-status/error blocks use synthetic atoms and ErrorRecords. Coverage here is the block's atom partition.

Atom = {id,kind:"field"|"manifest_row"|"unrecognized"|"synthetic",span:Span|null,raw_base64:string|null,raw_text:string|null,disposition,field_occurrences:FieldOccurrence[],cell_occurrences:CellOccurrence[],record_ids:string[],diagnostic_ids:string[]}. A field row is one atom even when malformed; a manifest row is one atom. Structural headers/separators are retained in block.structural_spans; malformed header/separator adds a synthetic unparsed atom anchored to its exact offending span. A table with no body has one synthetic atom. No atom is generated for excluded context; the file with no candidates gets one synthetic no-status/non-manifest atom. A synthetic atom with captured source has the whole relevant block span; unavailable source has null span. Every atom has at least one record link. Records and fields never allocate a second atom for the same source occurrence.

FieldOccurrence = {id,atom_id,key_raw,key_normalized,value_raw,value_text,span:Span,value_span:Span,disposition,diagnostic_ids:string[]}; every occurrence, including unknown/repeated keys, is present. CellOccurrence = {id,atom_id,column_index:integer,header_raw:string|null,header_normalized:string|null,value:CellValue,disposition,diagnostic_ids:string[]}. Cells beyond a short header and extra headers survive; missing trailing cells use explicit present=false value and no invented source span. CellValue = {present:boolean,raw:string|null,text:string|null,span:Span|null}. Absence is all null/false; an authored empty cell has present=true and exact empty/whitespace raw/span. Duplicate headers map to multiple occurrences, never a last-write object.

Record is the tagged union DevRecord | RoadmapRecord | ErrorRecord. DevRecord.kind="dev" and RoadmapRecord.kind="roadmap". All contain {id,kind,block_id,atom_ids:string[],span,raw_base64,raw_text,disposition,diagnostic_ids}. Every atom_ids member resolves in that block; reverse atom.record_ids is exact. ErrorRecord.kind="error", reason is one finite diagnostic code, and it has no selected status. It preserves orphan fields/malformed rows/synthetic errors through its atom_ids. A DevRecord covers all field atoms in one recognized panel/group, including failed metadata; a RoadmapRecord covers exactly one candidate body-row atom, including a malformed row. A header-level error atom uses ErrorRecord. No fake valid records are emitted for errors.

DevRecord additionally contains {package,feature,label_origin,title,workflow,executor,updated,suggested_next,current_phase,target,iteration,status,raw_status,field_ids,claim_countable}. All scalar metadata is string|null: absent or any duplicate key => null, with occurrences preserved. feature may use package only as a display fallback, labelled label_origin="package_fallback"; duplicate Feature remains null with label_origin="ambiguous", not fallback. target/iteration = {field_ids,raw_values,exact_value:string|null,ambiguity:null|"missing"|"duplicate"}. No heading/date/author iteration infers Target or iteration. status is StatusValue|null; raw_status is the sole Status.value_raw or null if missing/duplicate. field_ids contains every FieldOccurrence in atom/source order. One duplicate metadata key leaves all affected fields/atoms unparsed and record.disposition="unparsed"; other good atoms remain parsed. claim_countable is true if exactly one valid nonempty Status occurrence survives, regardless of unrelated metadata errors; false for duplicate/missing/empty/invalid Status or a structural error involving that Status atom. It counts a labelled source claim, not a successfully parsed package or winning business record.

RoadmapRecord additionally contains {filename,cell_ids,cells,status,raw_status,slug_exact,reference_values,claim_countable,unique_slug_eligible}. cells = {number,slug,status,source,depends_on,last_run,extra:CellOccurrence[]}; each named field is CellValue|null. null means duplicate header ambiguity, while absent column is {present:false,raw:null,text:null,span:null}. Every original cell remains in the atom even when a convenience cell is null. StatusValue lives ONLY at record.status; the raw Status CellValue lives at record.cells.status. slug_exact is a single valid nonempty slug text or null. raw_status is that one Status cell raw or null. Required header/width/Slug/Status errors set disposition unparsed and claim_countable=false. Missing optional Source/Depends On column is visible warning, not row rejection. Unknown nonempty Status is structurally parsed and countable as OTHER. Duplicate slug groups preserve each original RoadmapRecord, add E_SLUG_DUPLICATE to all members/atoms, set their dispositions unparsed, unique_slug_eligible=false and claim_countable=false; source cells and claims still render in source_parsing. A well-formed unique row sets unique_slug_eligible=true. The collector performs this cross-file duplicate annotation immutably after per-file parsing, recomputing all exact partitions; parsing a single file cannot establish cross-corpus uniqueness.

StatusValue = {raw:string,token:string|null,recognized:boolean,annotation_raw:string,claim_only:true}; null record.status is never converted into an asserted business state. Finite recognized tokens remain PENDING, IN_PROGRESS, NEEDS_REVIEW, APPROVED, READY_FOR_VERIFY, FIX_READY, FIX_READY_FOR_VERIFY, READY_TO_SHIP, SHIPPED, BLOCKED, BLOCKED_EXTERNAL, PAUSED. Remove only balanced outer emphasis/code and surrounding whitespace to recognize an isolated case-folded token. Only a whitespace-separated bracket/parenthetical or em-dash suffix is annotation, preserved verbatim. Unknown nonempty text is token=null, recognized=false, W_STATUS_UNKNOWN; "not shipped", "completed some phases", PENDING_INDEPENDENT_VERIFICATION cannot become SHIPPED. Empty/missing Status is an error. Original text is never rewritten.

ReferenceValue = {cell_id,kind:"none"|"repo_path"|"slug"|"markdown_destination"|"unresolved",raw:string,targets:string[],resolution:"not_checked",diagnostic_ids:string[]}. "-" gives none with targets=[]; one exact bare path/slug or each exact Markdown destination is lexical information only. Rich prose remains unresolved with W_SOURCE_REFERENCE/W_DEPENDENCY_REFERENCE. No comma-based dependency satisfaction, existence assertion, fetch or execution occurs.

Diagnostic = {id,code,severity:"info"|"warning"|"error",domain,path,owner_id,block_id:string|null,record_id:string|null,atom_ids:string[],span:Span|null,message:string,related_refs:{corpus_id,id}[]}. Every field's diagnostic_ids resolves to this file's diagnostics; related cross-file/corpus links are qualified. Directory diagnostics belong to CorpusResult and have no invented file/atom. Finite codes remain E_INPUT, E_HASH, E_DIRECTORY_READ, E_FILE_READ, E_PATH_CONTAINMENT, E_UTF8, E_TABLE_SEPARATOR, E_ROW_WIDTH, E_HEADER_DUPLICATE, E_REQUIRED_HEADER, E_STATUS_MISSING, E_STATUS_EMPTY, E_REQUIRED_CELL, E_DUPLICATE_FIELD, E_SLUG_DUPLICATE, E_SYNTAX; W_STATUS_UNKNOWN, W_TARGET_MISSING, W_ITERATION_MISSING, W_IDENTITY_AMBIGUOUS, W_SOURCE_MISSING, W_DEPENDS_ON_MISSING, W_SOURCE_REFERENCE, W_DEPENDENCY_REFERENCE, W_MODULE_UNASSIGNED, W_MODULE_MULTI_ASSOCIATION, W_STATUS_CONFLICT; I_NON_MANIFEST, I_NO_STATUS_BLOCK, I_EMPTY_FILE, I_EXCLUDED_CONTEXT. E_INPUT covers a missing/invalid envelope; E_PATH_CONTAINMENT covers collector-rejected members. No generic success catch is permitted.

### 4.4 Corpus conservation and association

Coverage = {discovered_ids:string[],parsed_ids:string[],unparsed_ids:string[],discovered:integer,parsed:integer,unparsed:integer}; arrays preserve source order, are unique/disjoint and exact-union; counts equal array lengths. Atom disposition is unparsed when any attached severity=error or synthetic no-source/no-candidate outcome applies; otherwise parsed. A block/file is parsed iff it has at least one candidate, all child atoms/blocks parsed and no own error; mixed files are unparsed but successful atoms and claim_countable records remain visible. Warning-only unknown Status does not become failure or shipment. Informational synthetic outcomes remain unparsed at every tier to expose discovered files with no records.

CorpusResult = {schema_version:1,corpus_id,domain,source_ref,inventory_paths:string[],discovery:{complete:boolean,directories:DirectoryReceipt[]},files:FileResult[],diagnostics:Diagnostic[],record_refs:{corpus_id,id}[],coverage:{files:Coverage,blocks:Coverage,atoms:Coverage}}. DirectoryReceipt = {id:"directory/N",path,enumeration:"complete"|"failed",entries:string[],read_error:{code,message}|null}. A partial enumeration failure keeps enumerated entries and files, records E_DIRECTORY_READ and complete=false; zero enumerated entries means zero *known* files, not proof of an empty repository. Distinguish unavailable unknown file totals from honest known-zero ID sets. record_refs enumerates every record including error records; legacy DTO projection separately selects claim_countable records.

All captured bytes reconstruct through parts; all discovered file/block/atom IDs are conserved even on errors. Every record resolves atom_ids and every atom resolves record_ids; every field/cell resolves its atom; every diagnostic resolves owner and existing related endpoints.
