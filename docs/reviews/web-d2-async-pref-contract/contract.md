## Shared mutation API and compatibility

Add explicit exported `usePrefAsync` and `usePrefAutosaveAsync` entry points. Exact internal factoring is an implementation choice, but the public Promise/result distinction and these semantics are mandatory:

- `usePrefAsync` exposes a committed snapshot, an async absolute/functional setter and async reset. Its metadata includes source state, pending operation, error and retry capability. Success returns the verified committed value/raw snapshot and whether bytes changed; refusal returns a typed reason. Do not return a Promise through the old boolean/void tuple.
- `usePrefAutosaveAsync` composes that mechanism, owns a local draft and exposes `edit(value)`, status and Promise-returning retry/reset. Editing is immediate; persistence is asynchronous. It may have a different signature from the old write-only hook because its name is explicit. Only this wrapper drives the selected select; it must actually exercise the shared async-pref path.
- Registered bindings use the registry key/codec/default plus a runtime domain validator. Open-ended autosave bindings must declare suffix, codec, default and validator; verify the resulting key and ownership. Reject a codec override inconsistent with a registered key. Default-share must retain physical strings such as `edit`, not JSON-quoted strings. Do not accept `String(object)` or truthy coercion as validation.
- Centralize strict read/validate/mutate/encode/remove/readback in one storage-owned engine. Existing explicit `setPrefAccount`, `removePrefAccount`, `setPrefAutosaveAccount`, `removePrefAutosaveAccount` must join its same-key serialization without changing their existing Promise-result signatures. Add a distinct richer result type for new snapshot/conflict semantics if needed. Existing absolute API calls without an expected baseline remain deliberate replacements, serialized with the updater; new draft hooks always supply a baseline.
- Preserve synchronous `usePref`, `usePrefAutosave`, set/remove and their device behavior for unconverted consumers. Keep their existing coordinated-admission refusal guards. Do not open admission or remove canonical protection to make tests pass. Scoped raw APIs, global settings reset and other legacy writers remain inventoried gaps; they are not made coordinated merely by introducing the hooks.

For the new engine, distinguish `absent`, `valid`, `invalid` and `unavailable` source states. Only physical `getItem(...) === null` permits the validated default as an initial mutation input. JSON null, malformed encoding, invalid enums and read exceptions cannot silently become absence or authorize a default write. Defaults may be displayed with explicit source/error metadata but must not be autosaved over an invalid/unavailable source. A valid empty domain value remains valid when its supplied validator allows it. Reset follows the same admission/source/baseline checks; this batch does not add an implicit corrupt-data deletion authority.

Both canonical dataset keys (`xai_task_cols`, `xai_calendar_events`) must be explicitly refused by the new generic mutation path. Do not unwrap and overwrite their envelopes, erase receipts through reset, or call their protected legacy setters. Their existing C/D1 domain engines remain the supported writers. Preserve existing compatibility behavior of older APIs and test it separately.

## Locking, baseline and publication

1. Capture the binding and scope before enqueueing. Resolve ownership through `accountOwnership`, not a blanket `xai_pref_*` assumption. Account writes take the existing generation-independent **account shared lock → physical-key exclusive lock**. Migration/deletion use the same account lock exclusively. The domain lock name must be derived unambiguously from the full physical key and shared by pref set/remove, autosave set/remove and functional mutation. Do not use a hook instance, API name, suffix alone or generation-only account lock name.
2. Recheck current captured owner, full persistent marker and tombstone after each lock wait, then before mutation/publication. No await is permitted inside the final localStorage read/validate/write/readback segment. Use an internal already-held-account helper; do not recursively call a public API that requests account coordination again. Use the bound native `navigator.locks.request(name, { mode }, callback)` adapter; no arity detection or fallback raw write on lock refusal.
3. New async device-pref mutations use only the same physical-key exclusive lock, without account current-owner, marker or tombstone requirements. This deliberately keeps their functional updates serialized; lock failure is a typed refusal even for that new API. Old synchronous device hooks retain their current behavior, and the first consumer's device toggles stay on those hooks.
4. Absolute draft writes/reset compare their captured physical raw baseline inside the key lock, before changing bytes. A different source returns `conflict`, preserving both external bytes and the local draft. Compare raw bytes, not projected/default values. Reset removes the key only after successful comparison; report default/absent only after confirmed removal. An ABA change ending in identical bytes is outside raw-snapshot detection; do not invent a revision key/envelope for this preference batch or claim a durable revision protocol.
5. An explicitly requested functional updater receives the latest strictly validated persisted value **inside** the exclusive key lock and runs once per granted attempt. Two independent increments must preserve both updates. It must not receive stale React state; validate its output before encoding. An optional supplied expected baseline additionally constrains it. A thrown updater/validator/encoder is a typed failure, with no write/notification. Updaters must be pure and synchronous; a retry is a new attempt against current data, not an exactly-once command receipt.
6. Same-value no-op still obtains the required locks and validates owner/marker/tombstone/source/baseline. It may then succeed without a set/remove or notification. Cache equality alone never authorizes Saved. After a physical write/removal, strictly read back the expected raw result; only verified success may advance the committed snapshot and publish once through the existing same-tab bus. Isolate observer exceptions from the committed result. A readback failure can mean bytes were written: return a failure with that uncertainty, do not roll back unknown bytes, and allow retry to verify the intended result safely before declaring success. If that recovery verifies a previously unannounced own commit, publish one reconciliation notification even when no second physical write is needed; the ordinary already-observed no-op rule must not strand sibling hooks on stale state.
7. Observe same-tab bus and cross-document storage changes by re-reading the physical binding and validating it, rather than trusting an old event payload. Clean controls adopt a valid new committed value. Dirty controls retain their draft and flag an external conflict; they must not silently replace their base or overwrite external changes. A retry after a storage/lock fault retains its original base, with a narrowly verified own-intended-value recovery for an uncertain commit. A real conflict requires an explicit reload/discard action; Retry is not implicit overwrite authority.

Locks coordinate participating current writers only. Old sync code can still write outside these locks while admission is off; source comparison is useful defense, not a universal legacy-client guarantee. No claim of atomicity across multiple preferences or stores is authorized.

## Hook operation and Settings UI contract

- Start clean from a valid persisted source or an absent default; do not write on mount merely because a default is rendered. Invalid/unavailable reads show an actionable failure and do not seed. The selected control must validate DOM input against the permission enum as well as validating persistence.
- Track a binding/session token and monotonically ordered edit/operation sequence. At most one persistence attempt for a binding is active; coalesce newer absolute drafts to the latest queued edit. Duplicate retry of the same active attempt shares its result. A prior success may advance the base for that binding's next local edit only when it is the verified predecessor, never after an external change. A prior failure stops automatic resubmission until a user retry/new edit; no busy retry loop.
- Latest draft stays visible while pending or failed. A completion for edit N must not mark N+1 Saved, revert N+1, clear its error incorrectly, or reopen a closed editor. New edits during an in-flight attempt must eventually save in order/coalesced form or remain visibly unsaved. Define `idle/dirty/pending/saved/error` explicitly; `saved` means the **current draft** is verified, not merely some prior Promise resolved.
- Reset is an ordered operation, not a local state shortcut. It invalidates older queued draft work. A reset refusal preserves the latest draft/error and previous committed source; success selects the default only if no newer edit superseded it. A later edit during reset remains queued with the proper successful-predecessor base. The Collaborate pane has no reset control today: exercise this API contract in hook tests without adding a new global/reset UI.
- Key/codec/scope changes and disposal invalidate the old session's callbacks and queued admission. An account change never retargets A's draft into B. Hide A's committed/draft state from B, disable the stale account control or reinitialize an explicitly new binding; returning to A creates a new session. Pending old callbacks cannot mutate that new session even for the same key. A commit already completed before unmount is not undone; no unload durability guarantee is added.
- Preserve live selection and no Save footer. Add accessible localized Saving / Saved / Not saved feedback next to the default-share control, a Retry action for retryable errors, and explicit reload/discard for conflict/source recovery as appropriate. Pending must not prevent collecting a newer selection. Device toggles remain usable across account changes and have no new account-lock dependency. Remove the void-result cast for the converted control and consume actual async results; catch injected Promise rejection at the hook/caller boundary.
- This pane has no draft export feature. Do not add unrelated export, import or sharing behavior. Navigating away need not create a durable draft store, but must not display a false saved confirmation. Keep existing EN/ZH labels and avatar/mention behavior.
