## Shared storage API and invariants

Add a targeted async `mutateCanonicalDataset<T>` alongside the command primitive. Input: canonical key, captured scope, owner domain guard, synchronous mutation computed from locked current data, optional absent-only initializer, and an explicit precondition for stale UI state. Return a discriminated Promise result (`ok/data/revision/changed` or a typed failure including conflict). Ordinary writes **do not invent AI request identities or success receipts**.

Factor shared internals in `plugin-web-storage/src/internal/canonicalCommandState.ts` (or a new adjacent internal file): identical physical-key lock naming, captured owner/marker/tombstone checks, result-bearing read, domain/encoded-output validation, capacity/revision checks, and single same-key write. Preserve every latest receipt, including literal own-property keys. AI commands and ordinary writers must acquire the same lock helper; do not duplicate subtly different names. Keep the final read/compute/write section synchronous with no unrelated await.

For snapshot replacement, carry the original physical state token or a domain baseline plus revision policy into the lock. Never compare against `getPref` defaults. A full revision mismatch may conservatively reject; alternatively a domain-baseline comparison may accept receipt-only changes while retaining the latest receipts. Either policy must reject a conflicting domain change. Semantic mutations may compute against latest data, with target-level preconditions where a composer edits a captured entity. Do not automatically rebase a failed whole-dataset draft over newer content.

Physical absent may initialize explicitly; legacy/envelope data must pass the owner guard, including null rejection. Domain clear/reset writes the domain's valid empty shape and **keeps receipts**, rather than removeItem. A genuine no-op may return committed unchanged with no write/revision bump. Existing receipt count 512 does not by itself forbid an ordinary edit that adds no receipt; byte/encoded-length and revision exhaustion still apply. Preserve original bytes on all precommit failures.

After a successful write, publish **domain data**, once, through the same-tab bus with captured scope; other tabs consume the keyed StorageEvent projection. Route command success and ordinary success through the same notification behavior, with no duplicate publication. A notification listener exception after commit must not turn a committed result into a failed save that encourages duplicate retry. Read-only `usePref` consumers remain compatible.

Production envelope activation remains closed pending the separate rollout gate. Once the coordinated protocol is activated, old synchronous `setPref/removePref` must refuse these two keys even when their current bytes are absent or legacy; otherwise they remain a lock bypass. Expose a targeted async hook/write surface instead of changing unrelated preferences' boolean API. `usePref.meta.reset` currently marks local default unconditionally after void removal (`usePref.ts:211–216`); canonical reset must await a real result and update state only on success. Do not enable production activation as part of this batch.
