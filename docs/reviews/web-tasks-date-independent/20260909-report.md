## Current behavior and source evidence

- `TasksModule.tsx:72` observes `useLocalDayClock`; `:90` groups by real `dueDate`, and `:137–145` computes counts and filtered columns from the same sampled date.
- `internal/filterCardsByList.ts:5–19` supplies the shared predicate: Today is valid `dueDate <= local today`; Tomorrow is exactly the next civil date; Next 7 Days is `(today, today + 7]`. `getSmartCounts` at `TasksModule.tsx:640` directly reuses that function, preventing a separate count predicate.
- `internal/groupTasksByDueDate.ts:5–29` regroups known dates without guessing a year for old labels. `date: "1/1"` is not a real dueDate and does not appear in any date smart list merely because the visible label matches.
- `plugin-web-tokens/src/useLocalDayClock.ts:5–28` resamples at midnight, focus, pageshow, visible-state return and at most a minute between clock/time-zone calibration. Civil date arithmetic does not add fixed 24-hour durations.

## Findings and recommendations

No blocking TASK-01 defect was found. Keep these explicit semantics documented: today includes overdue, future seven days excludes today and includes day +7, and old yearless labels need explicit user assignment before they qualify as calendar dates.

Optional UI wording improvement: the sidebar says **Next 7 Days**, while the top chip says **Next few days** (`TasksModule.tsx:811`). The actual predicate and counts agree, but matching the labels would make the seven-day boundary clearer. This does not block the current TASK-01 acceptance.

The first package harness attempt used repository-root cwd; two unchanged source-boundary tests then could not open their package-relative files. Running with the correct package cwd resolved the harness failure. A preliminary native visibility harness also mounted an unnecessary second Tasks instance with a different artificial clock; the final passive blank peer isolates the intended visibility test. No product assertion or implementation was relaxed to obtain PASS.
