## 4. Proposed pure API and complete data contract

The following is a proposed interface, not executable implementation. A future independent reviewer must approve the whole interface and impact before a writer is registered. Add scripts/dashboard/source-contract.mjs as the isolated pure reader; keep filesystem/Git collection in generate-state.mjs. It must not import the generator because that module performs top-level collection/writes.

| Proposed export | Input | Output / ownership |
|---|---|---|
| parseDevLogSource(input) | SourceInput | FileResult<DevRecord>, no I/O, no mutations |
| parseRoadmapSource(input) | SourceInput | FileResult<RoadmapRecord>, no I/O, no mutations |
| collectSourceCoverage(domain, entries, discoveryDiagnostics) | ordered SourceEntry[] plus directory-level diagnostics | CorpusResult; accepts explicit failed reads and does not drop entries |
| relateSourceRecords(devCorpus, roadmapCorpus, productLines) | immutable results and authored module registry | AssociationResult, exact matches/candidates/conflicts only; never writes or chooses authoritative status |

SourceInput = {domain: 'dev_log'|'roadmap', path: repo-relative string, source_ref: full SHA or explicitly labelled working-tree capture ID, source_sha256: 64 hex, bytes: Uint8Array}. SourceEntry is either that success input or {domain,path,read_error:{code,message},source_ref,source_sha256:null,bytes:null}. Verify the provided content hash before interpreting any bytes. UTF-8 decode is strict; CRLF/LF and BOM are preserved in raw storage and byte offsets. No filesystem/network/HTML evaluation occurs inside the pure module. Invalid arguments/hash mismatch produce explicit E_INPUT/E_HASH results; host programming faults abort collection with a failed receipt rather than fabricating an empty corpus.

SourceSpan = {start_byte,end_byte,start_line,end_line}; bytes are zero-based half-open offsets, lines are one-based inclusive. Empty files use the zero-width [0,0) span at line 1. Each FileResult stores {domain,path,source_ref,source_sha256,byte_length,raw_source,disposition,parts,blocks,records,diagnostics,coverage}. raw_source is the exact UTF-8 text for readable valid text; decode/read errors retain the byte hash or read-error identity and no invented text. parts[] is an ordered exhaustive non-overlapping byte partition labelled context or candidate, with span and raw; candidate parts point to block IDs. Fenced code and quotations remain context with explicit excluded_context reason unless they are themselves malformed candidate syntax described below; no discarded bytes.

BlockResult = {id,format,span,raw,heading_context,disposition,records,fields,diagnostics,coverage}. id is provenance, deterministically domain + source_ref + path + start_byte + end_byte + format; it is not a new business ID. format is table|bullet|plain|heading|unrecognized|file_error|empty. heading_context is the full ordered enclosing heading trail, each with raw title/span. Fields are ordered FieldOccurrence[] = {key_raw,key_normalized,value_raw,value_text,span}; duplicates never collapse into an object. A block can contain successfully extracted records and still be unparsed because of malformed material. Each candidate atom (field row, manifest row, heading value or status-like line) has its own provenance ID and parsed/unparsed disposition; structural rows/headers are retained in block metadata. No Map assignment may erase a duplicate.

DevRecord = {id,block_id,path,package,feature,title,workflow,executor,updated,suggested_next,current_phase,target,iteration,status,raw_status,field_occurrences,span,raw,diagnostic_ids}. Scalar convenience values are nullable when missing/duplicated; occurrences remain the source of truth. package is the directory name, never a surrogate Target. target and iteration each have {raw_values,exact_value:null|string,source_spans,ambiguity:null|string}; explicit field text supplies them. An absent Target/Iteration stays null. “Author Iteration”, “Vendor Verification”, dates, heading position and filesystem time remain separately named metadata; they are not silently converted to a product iteration. feature falls back to package only as a display label, with label_origin='package_fallback'; it never establishes identity. title/updated/next raw values and all unknown keys stay visible.

RoadmapRecord = {id,block_id,path,filename,span,raw,number,slug,status,raw_status,source,depends_on,last_run,extra_fields,diagnostic_ids}. Every cell is a CellValue {present:boolean,raw:string|null,text:string|null,span:null|SourceSpan}; number absent differs from an empty supplied #. slug additionally exposes exact_value only for one nonempty, structurally valid cell. Source and Depends On are always present in the output shape even if absent from a document, with explicit diagnostics. Never drop unknown columns, column order, empty values or original row width.

StatusValue = {raw,token:null|string,recognized:boolean,annotation_raw,claim_only:true}. Proposed finite recognized tokens: PENDING, IN_PROGRESS, NEEDS_REVIEW, APPROVED, READY_FOR_VERIFY, FIX_READY, FIX_READY_FOR_VERIFY, READY_TO_SHIP, SHIPPED, BLOCKED, BLOCKED_EXTERNAL, PAUSED. Strip only balanced outer Markdown emphasis/code delimiters and surrounding whitespace for token recognition; case-fold the isolated token. A recognized token may be followed by whitespace then a parenthetical/bracket annotation or em dash; keep the complete annotation. Other text is UNKNOWN with raw preserved. “not shipped”, “completed some phases”, and PENDING_INDEPENDENT_VERIFICATION must never become SHIPPED through substring matching. Existing UI status can project recognized token or OTHER, with exact token/raw beside it; FIX_READY_FOR_VERIFY remains distinguishable. Recognition is a source claim, not independent verification or shipment. Missing/empty Status is unparsed E_STATUS_MISSING/E_STATUS_EMPTY; unknown nonempty status is a parsed text value with W_STATUS_UNKNOWN, not an error or inferred completion.

Diagnostics are structured {id,code,severity:'info'|'warning'|'error',domain,path,block_id:null|string,record_id:null|string,span:null|SourceSpan,message,related_ids:string[]}. Finite codes: E_INPUT, E_HASH, E_DIRECTORY_READ, E_FILE_READ, E_PATH_CONTAINMENT, E_UTF8, E_TABLE_SEPARATOR, E_ROW_WIDTH, E_HEADER_DUPLICATE, E_REQUIRED_HEADER, E_STATUS_MISSING, E_STATUS_EMPTY, E_REQUIRED_CELL, E_DUPLICATE_FIELD, E_SLUG_DUPLICATE, E_SYNTAX; W_STATUS_UNKNOWN, W_TARGET_MISSING, W_ITERATION_MISSING, W_IDENTITY_AMBIGUOUS, W_SOURCE_MISSING, W_DEPENDS_ON_MISSING, W_SOURCE_REFERENCE, W_DEPENDENCY_REFERENCE, W_MODULE_UNASSIGNED, W_MODULE_MULTI_ASSOCIATION, W_STATUS_CONFLICT; I_NON_MANIFEST, I_NO_STATUS_BLOCK, I_EMPTY_FILE, I_EXCLUDED_CONTEXT. Codes describe parsing/provenance, never business release gates. A newly encountered unsupported syntax is E_SYNTAX with raw and span, not a new hidden catch-all success.

CorpusResult = {schema_version:1,domain,source_ref,inventory_paths,discovery_complete:boolean,files,diagnostics,coverage:{files,blocks,atoms},records}. Each coverage tier is {discovered_ids,parsed_ids,unparsed_ids,discovered,parsed,unparsed}; counters derive from unique identity sets, not vice versa. For every file and block and the corpus, discovered = parsed + unparsed with disjoint sets and exact union equality. A file is parsed only if it has at least one candidate and all its blocks/atoms are parsed; mixed/partial files are unparsed at file tier but retain all successful records and separate block/atom partitions. Non-manifest, empty and no-status files get one explicit synthetic unparsed block/atom and diagnostic, so their file identities cannot vanish. These categories are informative when expected, not silently converted to successful manifests. Directory enumeration failure sets discovery_complete=false and top-level E_DIRECTORY_READ; it cannot claim complete source conservation beyond the entries actually enumerated.

AssociationResult = {links,unassigned,conflicts,diagnostics}; each link preserves {roadmap_record_id,dev_record_ids,match:'exact_target'|'ambiguous'|'none',module_keys,registry_paths,iteration_relation:'equal_explicit'|'different_explicit'|'unknown'}. Module membership comes solely from exact authored filename associations, can be zero/one/multiple, and is not inferred from xai-web naming. Two explicit equal Target strings can be related as candidates; absent/nonunique iteration prevents declaring “current same iteration.” Conflicts contain both raw status/span/ref/hash values plus candidate relationship, not a winning status. Duplicate exact targets or slugs retain every occurrence.

## 5. GOV-01 finite recognition and conservation grammar

All recognition operates outside fenced code and Markdown blockquotes; those byte regions are kept as excluded context and the fixture oracle must demonstrate they cannot supply current status. ATX headings open an enclosing section until the next heading at the same or higher level. A file's H1 name does not supply a Target. Candidate discovery is broader than successful parsing: anchored field markers, Status headings, candidate tables and residual status-like lines are all retained. A plain prose sentence containing the word “status” is not automatically a workflow field; if it contains a standalone Status label/token outside recognized forms it is a raw unrecognized candidate with E_SYNTAX, never a silent state override.

| Format | Exact proposed recognition and boundary | Failure retention |
|---|---|---|
| Field/Value table | Header names normalized by trim, balanced inline wrapper removal and case-fold; distinct Field and Value required; column order arbitrary, extra columns retained. Starts at header+separator; ends before first non-table line. Keep every body row and header span. Status/Target/Iteration keys are case-insensitive exact field labels. | Missing separator/duplicate required header/short or long row produces diagnostics and raw row; no first-arbitrary-table fallback. |
| Bullet panel | Anchored -, * or + plus optional balanced emphasis around a field key followed by colon; consecutive field lines within the same section form a block; blank lines may separate metadata but a non-field prose line ends the run. | Duplicate key occurrences retained; an orphan field, empty status, or malformed Status-like line is explicit unparsed material. |
| Plain fields | Anchored key: value with the same key treatment and section/run boundary; no requirement for a “Status Panel” heading. | No merging across Work Log, Previous baseline or peer headings. Missing status retains a block. |
| Status heading | ATX heading whose entire normalized title is Status, optionally followed by colon and same-line value; otherwise first nonblank non-heading/non-list/non-table line is the value. Leading metadata fields following that value in the same section may be captured. | Missing value before the next heading is E_STATUS_EMPTY; multiple candidate value lines are not silently concatenated into a chosen status. |
| Multi-iteration | Each independent section/run/table is emitted; a repeated Target/Iteration begins a new candidate group when the prior group already has a Status; preserve container heading and field spans. | A repeated Status without explicit new group boundary is E_DUPLICATE_FIELD, with every occurrence retained and scalar status null. Same Target/iteration across blocks adds ambiguity; never last-row/first-row/latest-date wins. |
| Empty/unknown/malformed | Empty file or no recognizable status gets an explicit synthetic unparsed record. Unknown nonempty status is parsed with warning; malformed candidates retain exact bytes and locations. | Counts include all candidates, including unsuccessful or mixed blocks. |

Table lexical contract applies only to this proposed module, leaving parsePluginMap's current shared helper untouched. Optional outer pipes are delimiters, and inner unescaped pipes outside a matched backtick code span are delimiters. A backslash-escaped pipe is cell content; an even number of preceding backslashes does not escape it. Matched backtick runs of equal length protect inner pipes; unmatched runs produce E_SYNTAX instead of guessing. Encoded HTML pipe text remains raw text. Unescaped embedded pipes that change width produce E_ROW_WIDTH; never truncate excess cells or join them heuristically. Preserve source text and decoded text separately. Header separators require one cell per header and each trimmed cell to match optional colon, at least three hyphens, optional colon. Blank cells remain cells. Fenced examples with fake SHIPPED do not affect counters for actual status blocks, but remain covered as source context.

The recognized key vocabulary for convenience fields is Field/Value table key text plus Status, Target, Iteration, Feature, Title, Workflow, Executor, Updated, Suggested Next and Current Phase. Unknown keys remain FieldOccurrences. Duplicate identical metadata values still produce E_DUPLICATE_FIELD and nullable convenience scalar; this deliberately exposes the existing AI panel's repeated Executor/Updated rather than silently overwriting them. Structurally extracted valid Status/Target atoms remain available even when their containing file is partial. This keeps the three AI source claims observable without treating a metadata duplicate as permission to erase the entire source.

GOV-01 conservation is file AND block AND atom based. Source byte parts additionally cover all bytes, including context; offsets must reconstruct the complete raw source exactly. Discover once, preserve once, classify once; failed parse must reuse its discovered identity. Multiple format recognizers cannot emit the same atom twice: precedence is fenced/quoted exclusion, table, explicit heading value, anchored bullet, anchored plain, then residual unrecognized candidate; explicit structural block groups own all their child atoms. Precedence determines lexical ownership only, never business authority.
