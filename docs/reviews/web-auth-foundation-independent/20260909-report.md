## Author probe assessment and extra coverage

The author's native probe adequately checks cross-page publication, delayed remote logout, stale action rejection, OAuth envelope reload and inert legacy data, but did not cover actual SDK token refresh, native transaction abort, partial transient denial or consumed-code persistence failure. This independent runner pins a Git archive and adds those business checks. Existing focused suites exercise additional SDK callback deduplication and atomic publication details; their totals overlap and are not a product-wide coverage percentage.

The first extra assertion incorrectly equated `capture() === null` with locked state. The coordinator deliberately retains generation/owner metadata for captured cleanup retry, and its internal snapshot may retain the last SDK object. The final oracle checks `status === error` and rejection of a protected mutation before network; the live provider separately hides session/client unless authenticated. This does not waive a caller's status gating obligation.

## Explicit unresolved boundaries

- If the very first durable logout/revocation write fails, the durable active session remains. The coordinator reports error and does not claim success; explicit retry can finish. No test here proves durable logout intent survives destroying the page before any write succeeds. Do not interpret error latching as a durable cross-restart revocation receipt.
- Remote global logout may invalidate a newer session of the same server account. Local generation isolation cannot override server semantics. Remote failure/indeterminate state is not a durable server retry queue.
- Backend account deletion/revocation and retained access-token validity remain separate contracts. REL-06 cannot be closed from this local acceptance.
- Consumed authorization code plus lost session persistence requires a fresh authentication attempt; recovery cannot reconstruct the lost response.
- Direct use of obsolete shared-key SDK helpers or raw SDK auth mutation bypasses the coordinator contract. Production callers must use the integrated lifecycle API; another reviewer owns host verification.
