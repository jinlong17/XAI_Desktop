## I1 — P1: promised intermediate property history has no complete acquisition mechanism

**Location:** impact S `impact.md` §3.3, especially lines 75–85; implementation allocation §7. This is a static measurement-design finding, not an executed product failure.

The named mechanisms are synchronous coordinator/account-scope subscribers, a root MutationObserver with oldValue, a React Profiler callback, and requestAnimationFrame samples. MutationObserver reports DOM child/attribute/character-data mutations, not arbitrary assignments to live input properties such as `HTMLInputElement.value`. Profiler observes commit boundaries; rAF observes a later frame boundary. A WeakMap gives stable node identity but does not freeze the node's earlier property values. Removed-node references in mutation records are live objects, not immutable snapshots.

Consequently a same-node input can be assigned a wrong-owner value and restored within the same synchronous turn before those boundary samples. Likewise an inserted/removed subtree's input property can be changed before the observer drains. There need be no value-attribute mutation and no intervening coordinator publish. All named samples can equal the correct final state while the promised intermediate property history is absent. This counterexample concerns the report's explicit intermediate-input/mutation acquisition promise; it does not claim that every transient value was painted, nor demand observation of speculative React rendering. The commit/mutation/paint distinctions must be retained.

§3.3 says property values and detached snapshots must be captured and that unreconstructable history refuses. Those are desired outcomes, not a specified collector. An unobserved property assignment supplies no overflow/gap flag, so blindly returning CAPTURE_INCOMPLETE only for known gaps cannot detect this case. Existing actual-capture controls list same-node wrong text and detached wrong subtree, but do not explicitly require the property-only same-turn case or historical removed-node property capture. More negative-result schemas or replaying a supplied wrong row cannot close it.
