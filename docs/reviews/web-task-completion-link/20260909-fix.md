## Completed contract

- Actual UTC ISO `completedAt` on incomplete→complete; idempotent complete retains it; undo removes it; re-completion gets a new instant. Legacy completed records with no timestamp remain undated. Timestamp is generated when the command is built, so a retained failed-save draft retries the same completion instant.
- Targeted legacy `completed[]` records remain operable. Missing done implies true only in that compatibility container; explicit false is respected. The old completed-group checkbox now performs real undo instead of a no-op. Moves and edits retain source, timestamps and unrelated metadata.
- Board lookup uses boardId/cardId, ignoring historical listId for identity; normal Task `done` and legacy completion state are both recognized. Today Board links use Today/Overdue immediately, matching Tasks date grouping.
- Board creation saves a pending request first, ensures the Task second and acknowledges the Board third. Each stage reports failure. Task failure retains the original request across reload; acknowledgement failure preserves the already-created Task. Retry does not duplicate or overwrite user edits/completion. Unrelated legacy task-ID collisions reject before publishing a false link.
- Board/card/list movement and archive/restore retain link identity and completion. Unlink remains Board-only; it does not delete Task data.
- New pending Retry is 44 px high at a 390 px viewport. It is labelled as incomplete linking rather than saved success.
