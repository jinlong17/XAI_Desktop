# Account deletion must retain its captured auth cleanup receipt

The former orchestrator completed the local deletion receipt after business data and AI secrets, then separately cleared authentication. Auth IndexedDB failure therefore left no pending deletion receipt. A reload could not discover that participant through the recovery notice.

The receipt now uses **version 2** when a live coordinator provides a captured auth generation. Business generation and auth generation are stored separately, without tokens, keys or profile content. Local erasure and secret cleanup are followed by the captured coordinator cleanup, and only then the complete marker. Missing or failed auth cleanup leaves a retryable receipt. Recovery outside protected routes uses the provider's coordinator to revoke exactly that original generation with `remote:false`, preserving B or a newer A login. Successful live deletion no longer invokes a second shared cleanup. Navigation is still suppressed after replacement.

Version 2 is intentional: older version-1 readers reject the new participant set rather than falsely completing it. Old version-1 local-data receipts remain supported within their original participant scope; no historical auth generation is invented. Unknown-server-intent suppression now requires a validated receipt of the same business generation, including version 2.

## Evidence

The same three contract assertions fail against that module and pass against the current implementation: failed auth cleanup cannot complete; reloaded retry targets captured A after B replaces it; absent cleanup cannot complete. Logs preserve nonzero-before and zero-after results. This probe is React-independent/jsdom with a mocked auth participant, not real IndexedDB or real server acceptance. ## Remaining boundaries

This change does not resolve unknown server deletion outcomes, add a server receipt/query endpoint, grant production deployment approval, or guarantee persistence when the browser refuses the first receipt write. It does not make multiple localStorage keys and IndexedDB one atomic transaction. The underlying auth generation transaction supplies identity isolation; its native evidence remains separate. REL-06 remains open pending joint recovery verification and the other declared cleanup participants.
