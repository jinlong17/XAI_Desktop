# POMO-01/02 implementation evidence

Status: FIX_READY_FOR_VERIFY. Owner execution checks only; no independent or cross-vendor approval implied.

## Implementation

- Pure `sessionProtocol.ts`: versioned account-owner active state, revision/session identity, accumulated elapsed, deadline, paused and settlement-pending phases; strict validation.
- `sessionController.ts`: one package controller, subscribed by UI and lightweight application host. Same-origin Web Locks serialize commands for the account kind/id + **business data generation** + feature. Each callback verifies current scope/tombstone/generation and rereads canonical bytes. Auth IndexedDB generation is not used here.
- Start/pause/resume/reset publish only after durable writes. End captures the original command time even when its lock grant is late. Automatic completion uses original deadline. Pending write → idempotent history append → active clear is recoverable, not represented as a cross-key atomic transaction.
- Pending/history failure retains retry state and never emits a saved completion. A failed pending End write also retains the frozen draft in recovery export; retry after deadline still saves the original early End. Clear failure explicitly says history was saved but cleanup failed. Reopening pending state merges by stable id and preserves first recordedAt.
- Old account callbacks cannot write, export or show another account state. New observers filter snapshots before first effect to avoid stale-account content flashes. All history/active corruption preserves original bytes and blocks overwrite. Same id conflicting history is rejected.
- `xai_pomodoro_active` is included in registry/ownership/validator; account lifecycle/export keys increase38→39 (device count unchanged). Existing history arrays stay compatible. New rows add optional schemaVersion/deadline/recordedAt. Core event adds optional sessionId/recordedAt while durationMs remains elapsed.
- Host change is exactly import of `@repo/plugin-web-pomodoro/session-host` and mounting `<PomodoroSessionHost />` inside AccountDataGate ready children in `apps/web/src/providers/AccountStorageGate.tsx`. Bundle inspection finds no PomodoroModule/TimerRing/Overview/record-list/styles inputs in this subpath.
- UI no longer appends or emits before checking persistence. Recovery alert exposes retry and raw scoped JSON export; blocked actions are disabled. Existing smooth dot rendering stays on UI rAF; durable reconciliation is independent and React time display is gated by seconds.

## Boundaries for independent verification

No Web Locks means explicit read-only behavior, not a fake CAS fallback. Offline browser closure cannot deliver a scheduled sound/notification; it can recover the state and deadline. Notifications/events are best-effort after durable history and may be missed across process termination. Existing browser notification feature flag remains off.

An active payload belonging to a different account/data generation is preserved and requires recovery instead of silently rebinding it during migration. Raw export contains its original data. Nothing enables cloud sync or changes auth-generation coordination. Without successful pending persistence, an End draft survives route changes in the running app but cannot survive a whole process crash; the previously committed running/paused session still survives and is never falsely reported saved.

The shared protocol is documented for later timer owners; no cross-product framework was introduced. Independent reviewer should inspect the WAL cut points, stale handlers and multi-window proof before marking POMO-01/02 closed.
