## 总评(原审查)

> 这份 PRD 最大问题不是"不够细",而是细到了把 Console 外壳写成了多个业务模块的二次 PRD,导致范围、优先级、插件边界和 Phase 计划互相打架。

## 总评(v0.2 响应)

v0.2 的核心动作是**范围收敛 + 契约硬化**:

1. **范围收敛**:把 Todo 图片粘贴 / 批改字段 / 批 Label / 批移清单 / 复杂 RRULE UI / 账号 / 数据库 vacuum / 插件管理 / 完整日历 / 习惯热力图等越界内容移交对应业务 plugin PRD;Console 只描述"如何承载",不定义"承载什么具体能力"。多选**仅保留批删除**(v0.2-rev1 撤回了 v0.2 的"批 Label / 批移清单"边界微调,严格对齐父 PRD §5.2 line 189)
2. **优先级重定义**:P0/P1/P2 拆成 P0-Shell / P0-View / P0-Project / P1-Phase3 / P2-Later 五个标签,M2.5"必过"含义可测试
3. **ConsoleView 契约硬化**:`PLUGIN_SDK §3.1` 中 `ConsoleView?: React.ComponentType` 裸接口扩展为完整的 ConsoleViewProps + ConsoleHostCapabilities + ConsoleSlotApi + FocusApi + SelectionApi + TelemetryApi 契约(PRD §7.2.1),并在 dev-plan W1 D1 标为硬阻塞
4. **键盘可达**:每个拖拽 / 右键 P0 操作内嵌键盘等价路径,并在 §5.6.4 整合成对偶清单,验收按此跑
5. **跨窗口一致性**:引入 entity_change_log + 事件 ack + 30s reconcile 三层保障,替换 v0.1 不可行的"两边都监听 SQLite"
6. **验收四层**:Shell / Module / Project / 灰显占位 / 跨窗口脚本五层并列,Phase 3+ 模块允许灰显但有清晰占位/不可达状态
