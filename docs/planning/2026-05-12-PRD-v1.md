## 1. 产品愿景与定位

### 1.1 一句话定位

XAI_Desktop 是一款 macOS 桌面增强应用,通过"浮动智能容器(Grid)+ AI Cube"重构 Mac 桌面的整理与日常效率体验,让用户在不离开桌面的前提下完成文件整理、任务管理、剪贴板调用、即时信息查看等高频操作。

### 1.2 北极星指标

**每位活跃用户每周打开 App 主面板(Control / Clipboard / Grid 交互)≥ 30 次**——验证"桌面级随手可达"的核心价值。

### 1.3 设计原则

1. **桌面优先**:所有功能不应迫使用户离开桌面进入独立 App 窗口;核心交互发生在 overlay 和浮动组件上。
2. **统一容器**:所有内容(文件、Todo、剪贴板、时钟、AI 对话)都封装为 Grid 的一种 ContentType,框架级一致。
3. **本地优先,云端兜底**:数据先写本地 SQLite,云同步是增强功能而非依赖;离线 100% 可用。
4. **隐私可见**:任何收集/上传都有显式开关 + 当前状态可见(剪贴板录制中、屏幕共享自动隐藏、敏感数据过滤等)。
5. **苹果美学**:间距、动效、字体、颜色严格遵循 Apple HIG;不堆 Windows 风的边框和阴影。
6. **可扩展骨架**:新增功能 = 新增一个 plugin 包 + 一行注册;不动核心。

### 1.4 2026-05-19 高级审查结论

> 本节基于三份主规划(`PRD` / `product-development-plan` / `REFACTORING_PLAN`)、三个子 PRD(Console / Web / Sync)和当前代码结构的交叉审查。结论:产品方向成立,但主 PRD、开发方案和重构方案存在**版本漂移**。本补丁把 v1 的定义从"功能全集口号"升级为"全集愿景 + 可执行门控"。

**审查判断:**

1. **对标产品目标需要从"功能复制"改为"场景叠加"**。XAI 不是单独做一个 Desktop Organizer、TickTick、Trello 或 Clipboard Manager,而是把"桌面分区 + 拖拽货架 + 本地剪贴板 + 深度控制台 + 零知识同步"组合成一个 Mac 桌面工作台。
2. **v1=全部 16 模块可以保留为 Owner 战略选择**,但开发必须按"价值闭环"分层验收:先证明桌面层成立,再上效率模块,再上 Console/Web/AI。任何后续模块不得绕过 Phase 0 的 R-00 技术门。
3. **美学目标要独立成可验收规格**,不能只写"苹果美学"。XAI 的视觉要避开 Windows 桌面围栏感、网页 SaaS 卡片堆叠感和游戏化噪音,以 macOS 原生、低干扰、玻璃/材质克制、键盘优先为准。
4. **Sync/Web 子 PRD 已明显高级化**,但主路线图仍有旧工期。Web 子开发方案已把 Phase 4.5 从 4-6 周修正为 8-10 周;Sync 子 PRD v0.6 已把协议硬化、TLA+、nonce lease、设备配对、Re-key 等列为真实阻塞项。主 PRD 必须接受这些成本。
5. **重构方向不是"从零拆微内核"**,当前代码已存在 `packages/core`、`packages/core-data`、`plugin-account`、Rust `commands/crypto/platform` 等基础;后续重点是收敛边界、补齐 `plugin-console/productivity/project/labels/widgets` 和清掉 Host 残余业务。

**执行门控:**

| Gate | 通过条件 | 不通过处理 |
|---|---|---|
| G0 · 桌面形态成立 | 真机证明 click-through / Grid 原生 DnD / Spaces / 多屏 / Control 稳定 | 降级为纯多窗口桌面工作台,暂停 overlay 叙事 |
| G1 · 本地价值闭环 | Organizer + Clipboard + Todo/Pomodoro + Menu bar + SQLite 本地加密可日用 | 不启动 Console 深水区 |
| G2 · Console 成立 | 三栏外壳 + P0 View + Project + 跨窗口一致性脚本全过 | Web 延后 |
| G3 · 零知识同步成立 | Sync v0.6 协议硬化 + 单表端到端 + 恢复/Re-key 演练过 | Web/多端营销不上线 |
| G4 · Web 成立 | Sync blob driver + IndexedDB 安全模型 + CSP/Sentry/导出/设备撤销过 | Web 只保留私测 |

## 2. 目标用户与典型场景

### 2.1 用户画像

| 画像 | 描述 | 痛点 |
|---|---|---|
| **P1 · 数字游民/远程办公者** | 25-40 岁,Mac 重度使用,每天处理大量文件、截图、链接、临时文本 | 桌面乱、找不到上周复制过的东西、Todo 散落多个 App |
| **P2 · 开发者/创作者** | 经常 Cmd+C 代码片段、API key、命令;需要剪贴板历史 + JSON 格式化 + Base64 | 现有剪贴板 App 要么卡顿、要么隐私不放心、要么不够"贴身" |
| **P3 · 自律实践者(GTD/番茄工作法)** | 想把 Todo + 番茄 + 习惯打卡塞进日常,但又不想再打开一个清单 App | 滴答清单太重,Sticky Notes 太轻,缺乏桌面级载体 |

### 2.2 典型场景(Hero Scenarios)

**场景 A · 一日工作流**
> 早上 9:00,小李打开 Mac。XAI_Desktop 的 Control 窗口显示今天的 Todo(3 项),时钟 Widget 显示北京/纽约时间,天气 Widget 显示当前 18°C 多云。他从 Finder 拖一份 PDF 到桌面的"今日材料"格子,然后 Cmd+Shift+P 启动番茄钟绑定第一项 Todo。25 分钟后,自动弹通知"小休 5 分钟",冥想模式按钮在 Control 上闪了一下。

**场景 B · 信息收集**
> 下午,小李在浏览资料,Cmd+C 复制了 12 段文本、3 张图、4 个链接。开会时他 Cmd+Shift+V 唤起剪贴板面板,按"链接"筛选,把 2 个关键 URL 拖到桌面的"会议参考"格子。会后他在剪贴板里搜"endpoint",找到上午复制的一段 JSON,按下"格式化"按钮直接得到 indent 版。

**场景 C · 任务整理**
> 周日晚,小李打开 XAI 的 Todo 日历视图,把下周的任务按日分配。设置一个新习惯"每天 22:00 前关电脑",AI Cube 提示"你最近 3 周这个习惯达成率 67%,要不要把目标调整为'22:30 前'?"(Phase 4)

## 3. 核心价值主张

**对 P1**:打开 Mac 不再面对一堆乱图标——文件、链接、应用自动分类到浮动格子,需要时一眼可见,不需要时格子可吸附到屏幕边缘隐藏。

**对 P2**:本地、隐私、快、全类型的剪贴板 + 程序员小工具内置(JSON / Base64 / URL / 时间戳),不再开十个 tab。

**对 P3**:把 Todo / 番茄 / 习惯打卡当成桌面"小元件"而不是清单 App,降低使用门槛 → 提高执行率。

## 5. 功能模块详细规格

### 5.1 智能桌面整理(Smart Container)

#### 5.1.1 概述

桌面上漂浮的可拖动、可调整大小的"格子",用户把文件、文件夹、应用、链接拖入其中,Grid 自动展示图标缩略图与标签。多个 Grid 通过统一布局管理。

#### 5.1.2 功能需求(FR)

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-DT-01 | 新建 Grid | Control 窗口点击"+ 新建格子"或快捷键 `Cmd+Shift+N`,生成默认 320×320 的空 Grid;支持命名 |
| FR-DT-02 | 拖入文件/文件夹 | 从 Finder 拖入,显示原生图标 + 文件名,数据指向原路径(不复制) |
| FR-DT-03 | 拖入应用程序 | 拖入 .app 或从 /Applications 列表选,点击启动 |
| FR-DT-04 | 拖入链接 | 拖入 URL(或浏览器标签拖出),显示 favicon + OG 标题 + 描述 |
| FR-DT-05 | 自动分类规则 | 用户配置规则(扩展名/类型/正则匹配),桌面新增文件触发自动归入对应 Grid |
| FR-DT-06 | 一键整理 | Control 上一个按钮,把当前桌面散乱图标按规则归类(规则为空时按文件类型默认分组) |
| FR-DT-07 | 退出桌面整理 | 隐藏所有 Grid,恢复原生桌面(数据不丢) |
| FR-DT-08 | 文件夹映射 Grid | 创建特殊类型 Grid,绑定某个真实目录,实时同步该目录内容(增/删/改) |
| FR-DT-09 | Grid 拖动 / Resize | 8 方向 Resize、自由拖动、贴边吸附 |
| FR-DT-10 | Grid 边缘吸附隐藏 | 拖到屏幕边缘,Grid 部分隐藏,鼠标悬停弹出 |
| FR-DT-11 | 内容缩略图 | 图片显示缩略图,PDF 首页缩略图,视频显示封面帧 |
| FR-DT-12 | 右键菜单 | Grid 右键:重命名 / 删除 / 锁定 / 设置;Item 右键:在 Finder 显示 / 打开 / 移除 |
| FR-DT-13 | 全局快捷键 | `Cmd+Shift+D` 切换 overlay 显示/隐藏 |
| FR-DT-14 | 多 Space 行为 | v1 共享一份布局(所有 Space 看到同一组 Grid);v2 再做 per-Space |

#### 5.1.3 数据模型对应

`grids` 表 + `grid_items` 表(参见 §8)。

#### 5.1.4 边界与降级

- 若用户系统未授予完全磁盘访问 → 提示授权,授权前只能拖入,不能扫描自动分类。
- 文件夹映射 Grid 性能:目录超过 1000 项时分页,优先展示最近修改。

### 5.2 待办清单(Todo · 中度复刻)

#### 5.2.1 概述

桌面级轻量 Todo,但提供子任务、标签、优先级、四种日历视图(年/月/周/日)、**四象限(Eisenhower Matrix)视图**。**不做**看板、甘特图、团队协作、附件、批量操作、自定义视图编辑器。

#### 5.2.2 功能需求

| ID | 需求 | 备注 |
|---|---|---|
| FR-TD-01 | 新建 Todo | 标题、描述、日期、优先级(低/中/高/紧急)、标签、所属清单、**重要性 × 紧急性维度(供四象限用)** |
| FR-TD-02 | 子任务 | 一级子任务(不支持嵌套子任务) |
| FR-TD-03 | 多清单 | 用户可创建多个清单(默认"收件箱"/"今天"/"本周"三个智能清单) |
| FR-TD-04 | 标签系统 | **接入全局 Label 系统(§5.11),不再是 Todo 私有标签** |
| FR-TD-05 | 优先级排序 | 四级优先级 + 拖动手动排序 |
| FR-TD-06 | 日历视图 | 年/月/周/日 四种视图切换 |
| FR-TD-07 | 重复任务 | 每天/每周/每月/自定义 cron |
| FR-TD-08 | 提醒通知 | 系统 Notification Center,可设置多个提醒(任务前 5/15/30/60 分钟) |
| FR-TD-09 | Todo 格子 | 一个 Grid 类型 = 显示某清单的 Todo 列表(同 Mac 桌面便签风格) |
| FR-TD-10 | 完成/恢复 | 勾选完成,5 秒内可撤销;已完成项保留 30 天后归档 |
| FR-TD-11 | 全局快捷键 | `Cmd+Shift+T` 快速新建 Todo |
| FR-TD-12 | 与番茄钟联动 | 任意 Todo 可一键开启番茄钟,完成番茄记入该 Todo |
| **FR-TD-13** | **四象限 / Eisenhower Matrix 视图** | 四宫格视图按"重要 × 紧急"两维度分类任务:① 重要且紧急 ② 重要不紧急 ③ 紧急不重要 ④ 不重要不紧急。任务可在象限间拖动(拖动即修改其重要性/紧急性)。每个象限可设独立颜色。参考滴答清单四象限实现。 |
| **FR-TD-14** | **象限默认映射** | 若用户没显式设重要性/紧急性,从优先级(紧急→象限①、高→②、中→③、低→④)默认推导,用户可手动覆盖。 |

#### 5.2.3 不做(明确)

- 看板视图(Kanban)
- 甘特图(Gantt)
- 协作/分享/评论
- 附件上传
- 自定义视图编辑器
- 任务依赖关系

### 5.4 习惯打卡(Habits · P1)

#### 5.4.1 概述

习惯打卡支持两种载体:桌面 Habit 格子(快速打卡)+ 控制台内的习惯详情页(完整日历/统计视图,参考滴答清单习惯模块的视觉与信息架构)。

#### 5.4.2 功能需求

#### 5.5.3 性能要求

- 监听新内容到入库延迟 < 100ms
- 搜索 1 万条记录返回 < 200ms
- App 后台常驻 CPU 占用 < 0.5%

#### 5.5.4 对标增强(2026-05-19)

Raycast Clipboard History、Maccy 和 Paste 类产品已经把"搜索历史 / 类型过滤 / OCR / 置顶 / 顺序粘贴 / 禁用应用"变成高级用户预期。XAI 的剪贴板模块要避免只做一个"历史列表",P0 验收增加以下产品判断:

| 能力 | P0 验收口径 | 差异化理由 |
|---|---|---|
| 类型过滤 | `Text / Images / Files / Links / Emails / Colors` 至少覆盖前 4 类;后 2 类可 P1 | 与 Raycast 预期对齐 |
| 禁用应用 | 初始内置 Passwords / Keychain Access / 常见密码管理器,用户可增删 | 隐私信任底线 |
| OCR 模式 | 允许用户选择 Fast / Accurate 或"仅手动 OCR" | 避免后台 CPU 被 OCR 拖垮 |
| 顺序粘贴 | 超时重置时间可配置(默认 30 秒) | 表单填写场景高频 |
| AI 入口 | Phase 4 只做"把选中剪贴板项作为上下文发给 AI",不默认全量索引到云端 | 符合本地优先与零知识承诺 |

### 5.13 整体控制台(P0,新增)

#### 5.13.1 概述

除了"桌面 overlay 模式"(浮动格子 + AI Cube + Widgets),产品还提供一个**完整的窗口化控制台**——类似滴答清单桌面端的布局:左侧 sidebar 导航 + 中间列表 + 右侧详情面板。这是用户做"深度任务/习惯/日历管理"时的主界面,与桌面 overlay 共享同一套数据。

#### 5.13.3 设计说明与范围控制

- 控制台**不是新功能集合**,而是已有模块(Todo/习惯/番茄/日历/标签/搜索/设置)的一个**统一窗口化外壳**。绝大部分业务逻辑复用 plugin 包,控制台只做布局和导航。
- 控制台**不做** Todo 的看板/甘特/协作(与 §5.2.3 一致)。
- 原 PRD 中的 "Control 窗口(AI Cube + Settings)" 与控制台的关系:**Control 窗口保留为 overlay 模式下的轻量快捷托盘;控制台是独立的完整窗口**。两者并存,职责不同。

#### 5.13.4 数据模型对应

控制台无独立数据表,复用所有已有表。新增一个 sidebar 布局偏好存 `settings`。

### 5.14 项目管理(Trello 式看板,P0,新增)

#### 5.14.1 概述

一个**仿 Trello 的可视化项目管理模块**:一个"项目看板(Board)"代表一个项目/工作流,看板里有若干"列(List)"代表阶段(如 Not started / In progress / Done),列里有"卡片(Card)"代表具体子功能/子任务。支持多个项目并行、用颜色区分管理。

**与 Todo 的区别(明确,不重复)**:
- **Todo(§5.2)** = 个人轻量待办,清单式,适合"今天要做的事"
- **项目管理(§5.14)** = 看板式,适合"一个项目下并行追踪很多子功能/子任务的完成状态"(参考用户场景:科研任务追踪——每篇论文/每个子课题一张卡)

> 注:决策 D(§方案文档)定的"Todo 不做看板视图"依然有效——看板不是塞进 Todo,而是**独立的项目管理模块**。两者数据可互通(卡片可关联 Todo),但形态分离。

#### 5.14.2 功能需求

| ID | 需求 | 备注 |
|---|---|---|
| FR-PJ-01 | 创建项目看板 | 名称、颜色、图标/Emoji;支持多个看板并行 |
| FR-PJ-02 | 列(List)管理 | 每个看板有可自定义的列;默认三列 Not started / In progress / Done;列可增删改、拖动重排 |
| FR-PJ-03 | 卡片(Card) | 标题、描述、颜色标签、截止日期、所属列;卡片即"子功能/子任务" |
| FR-PJ-04 | 拖拽流转 | 卡片在列间拖动改变状态;卡片在列内拖动改变排序 |
| FR-PJ-05 | 卡片详情面板 | 富文本/Markdown 描述、checklist 子任务清单、链接附件、备注(单人,作为笔记) |
| FR-PJ-06 | 颜色标签 | 接入全局 Label 系统(§5.11),卡片可挂多个 Label,按颜色快速区分 |
| FR-PJ-07 | 多视图切换 | 看板(Kanban)视图 + 表格(Table)视图 + 总览视图(参考用户截图的 Project/Processing/Table/Manager tabs) |
| FR-PJ-08 | 卡片 ↔ Todo 互通 | 看板卡片可关联或转化为 Todo;反之亦可 |
| FR-PJ-09 | 与桌面日历联动 | 有截止日期的卡片汇入桌面日历(§5.12) |
| FR-PJ-10 | 看板桌面 Widget | 一个 Grid 类型 = 某看板的精简版(显示各列卡片数 + 进行中卡片) |
| FR-PJ-11 | 控制台集成 | 项目管理作为整体控制台(§5.13)sidebar 的一个模块 |
| FR-PJ-12 | 卡片归档 | 完成的卡片可归档,看板保持整洁;归档区可查 |

#### 5.14.3 不做(明确,v1)

- 多人协作 / 卡片指派给他人 / @提及(v1 单人,与 §5.2.3 一致)
- Trello 的 Power-Ups / Butler 自动化(v2 可评估)
- 卡片文件附件上传到云(v1 只支持链接附件)
- 复杂自动化规则

#### 5.14.4 数据模型对应

`boards` / `board_lists` / `board_cards` / `board_card_checklist` 表(参见 §8)。颜色标签复用全局 `label_assignments`(`entity_type = 'board_card'`)。

### 5.15 网页版(Web Console,P0,新增)

#### 5.15.1 概述

整体控制台(§5.13)的**浏览器版本**——把控制台搬到 Web,形成"桌面 App + 网页版"的多端生态(参考滴答清单的全平台策略:Mac / Web / 浏览器插件 / 移动端)。网页版**复用控制台的 React 组件**,但数据层从本地 SQLite 切换为直连后端 API。

#### 5.15.2 功能需求

| ID | 需求 | 备注 |
|---|---|---|
| FR-WEB-01 | Web 控制台 | 在浏览器中提供与桌面控制台一致的 sidebar + list + detail 体验 |
| FR-WEB-02 | 功能子集 | 包含:Todo / 项目管理 / 习惯 / 桌面日历 / 标签 / 全局搜索 / 设置。**不含**桌面 overlay、剪贴板监听、桌面 Widgets、冥想模式(这些依赖 macOS 原生能力) |
| FR-WEB-03 | 账号登录 | 浏览器内完成邮箱/OAuth 登录,与桌面 App 同一账号 |
| FR-WEB-04 | 实时同步 | 网页版 ↔ 桌面 App 通过后端实时同步,数据一致 |
| FR-WEB-05 | 响应式布局 | 适配桌面浏览器宽屏 + 平板;手机浏览器为只读/精简(完整移动端是 Phase 5+ 的伴侣 App) |
| FR-WEB-06 | 部署 | 静态前端托管(Vercel / Cloudflare Pages)+ Supabase 后端 |
| FR-WEB-07 | 浏览器扩展(P1) | 快速捕获插件(选中网页内容一键存为 Todo/卡片),参考 TickTick/Trello 扩展;v1 P0 不做,P1 评估 |

#### 5.15.3 架构影响(重要)

网页版不是"另写一个 App",但有几个**从 Phase 2.5 起就要做对的架构约束**:
1. **控制台 React 组件必须平台无关** — 不能 import 任何 Tauri/原生 API,所有原生能力通过依赖注入的 `host` 接口提供
2. **数据访问层抽象** — `core-data` 要同时支持"本地 SQLite"(桌面)和"后端 API"(网页)两种 driver
3. **`plugin-console` 包要能在纯浏览器环境构建** — 单独的 web build target
4. **后端要承载完整 Web 应用** — 不只是同步,而是网页版的唯一数据源

#### 5.15.4 数据模型对应

无新增表。网页版与桌面 App 共享同一套后端数据库 schema。

### 5.16 AI 桌面宠物(Desktop Pet,P1,新增 · 初版)

> 本节为**初版规格**,后续可迭代。参考:OpenAI Codex 于 2026-05 上线的 Pet Mode(像素宠物浮于所有窗口之上,反映 AI 运行状态)、Docko / openpets / Live2D 桌宠等形态。

#### 5.16.1 概述

一只浮在桌面 overlay 上的虚拟宠物,身兼三职:
1. **陪伴** — 像素 / Live2D 风格,跟随鼠标、idle 动画、轻互动,降低长时间面对屏幕的孤独感;
2. **状态指示器** — 反映 XAI 自身状态(同步中 / 番茄钟工作中 / AI 思考中 / 有 Todo 到期 / 习惯待打卡),不用打开面板就能一眼感知(借鉴 Codex Pet 的核心理念:把后台状态变成可感知的情感化形象);
3. **AI 化身** — Phase 4 后作为 AI Cube 的"表情 / 对话入口",点击即可对话。

桌宠本质依赖桌面 overlay,**主要存在于 macOS App**;控制台 / 网页版不做浮动桌宠(可选:显示一个静态宠物头像作为装饰)。

#### 5.16.2 功能需求

| ID | 需求 | 备注 | 阶段 |
|---|---|---|---|
| FR-PET-01 | 浮动桌宠 | 浮于桌面 overlay 之上,可拖动、可贴边吸附、可一键隐藏 | Phase 3 |
| FR-PET-02 | 预置宠物 | 内置 6~8 个像素风预置形象,用户可切换 | Phase 3 |
| FR-PET-03 | 鼠标互动 | 跟随鼠标、点击有反应(摸头等轻互动)、idle 动画(打盹 / 溜达) | Phase 3 |
| FR-PET-04 | 状态指示器 | 用动画 / 表情反映 XAI 状态:同步中 / 番茄工作中 / 番茄休息 / AI 思考中 / Todo 到期 / 习惯待打卡 | Phase 3(AI 思考态留 Phase 4) |
| FR-PET-05 | 气泡提醒 | 宠物头顶气泡推送轻量提醒(番茄结束 / Todo 到期 / 习惯打卡),比系统通知更柔和 | Phase 3 |
| FR-PET-06 | 行为设置 | 活跃度、是否跟随鼠标、是否出声、勿扰时段、屏幕共享时自动隐藏(复用剪贴板的屏幕检测) | Phase 3 |
| FR-PET-07 | 声音(可选) | 轻量音效,默认关,可开 | Phase 3 |
| FR-PET-08 | 快捷键 / 入口 | 全局快捷键切换显隐;Settings > 外观 > 桌宠;控制台也有设置入口 | Phase 3 |
| FR-PET-09 | AI 对话化身 | 点击桌宠唤起 AI Cube 对话,桌宠作为 AI 的表情层 | Phase 4 |
| FR-PET-10 | 自定义宠物 / 孵化 | 用文字描述或上传图片,AI 生成一套动画帧(idle / 走 / 跳 / 挥手),借鉴 Codex hatch-pet | Phase 4 |
| FR-PET-11 | 长期记忆 | 桌宠记住用户偏好 / 习惯,基于 AI 模块的记忆能力,对话更个性化 | Phase 4 |

#### 5.16.3 初版范围控制(明确)

- **v1 初版只做 Phase 3 的基础桌宠**(FR-PET-01~08):预置形象 + 互动 + 状态指示 + 气泡提醒。
- AI 相关能力(对话化身 / 孵化 / 记忆)随 Phase 4 AI Cube 一起做。
- 初版**不做**:宠物养成系统(喂食 / 洗澡 / 成长)、宠物商店、多宠物同屏、宠物间互动。

#### 5.16.4 数据模型对应

`pets` 表(宠物定义:预置 + 孵化的自定义)+ `pet_memory` 表(Phase 4 长期记忆);当前激活的宠物 ID 存 `settings`。参见 §8。

### 5.17 产品美学与体验规格(新增)

> 目标:功能对齐竞品,美学超出竞品。XAI 第一眼必须像一个"为 Mac 原生工作流设计的桌面系统组件",而不是 Electron 工具箱、Windows 桌面围栏或营销页式 SaaS。

#### 5.17.1 视觉北极星

| 面 | 审美目标 | 禁止项 |
|---|---|---|
| Overlay / Grid | 低干扰、轻玻璃、可读、像桌面空间的一部分 | 厚边框、重阴影、彩色卡片堆、霓虹渐变 |
| Control / AI Cube | 状态清晰、短路径、像菜单栏扩展而非聊天玩具 | 把 AI 对话做成主屏;不稳定时假装智能 |
| Console | TickTick / Things 级信息密度 + macOS 原生三栏 | 网页后台风格大 hero、嵌套卡片、过大圆角 |
| Web | 与 Console 同构,只因平台限制而降级 | 另起一套视觉语言 |
| 桌宠 | 轻陪伴 + 状态表达 | 养成游戏化、强干扰、默认发声 |

#### 5.17.2 Design Tokens 验收

| Token | 默认值/规则 |
|---|---|
| 字体 | System font stack;正文 13-14px;控制台列表 13px;不随 viewport 缩放 |
| 圆角 | 工具/面板 8px;小控件 6px;桌宠气泡可 10px;禁止大面积 16px+ 卡片化 |
| 间距 | Console 使用 8px 基线;列表密度 Comfortable / Compact 两档 |
| 材质 | Overlay 可用低强度 blur/vibrancy;Console 以不透明/半透明分层,保证对比度 |
| 色彩 | 跟随系统 accent;功能色只用于状态和 label;避免单一紫蓝或深蓝主题统治全局 |
| 动效 | 100-180ms,只用于状态转移;尊重 Reduce Motion |
| 可访问性 | 关键文字对比度 AA;所有图标按钮必须有 tooltip / aria-label |

#### 5.17.3 竞品审美定位

| 竞品 | 可学 | 不学 |
|---|---|---|
| Apple Finder / Stacks | 桌面对象的轻量组织、Tags/Sort 心智 | Stacks 不可自定义工作流,不够项目化 |
| Desktop Organizer - File Zones | 分区、快速访问、App Zone / File Zone 区分、本地无收集叙事 | 视觉容易工具化;XAI 要更原生、更少装饰 |
| Dropover / Yoink | 拖拽临时货架、拖入/拖出过程的低干扰反馈 | 不把 XAI 降级成单次拖拽暂存工具 |
| TickTick | Sidebar + list + detail、日历/番茄/习惯一体 | 团队/深度清单全量复刻 |
| Things | Apple 生态感、克制、内容优先 | 封闭生态导致 Web 缺席 |
| Raycast / Maccy | 键盘优先、快、隐私可信 | 纯命令面板/纯剪贴板不承载桌面空间 |
| Trello | Board/List/Card 心智清晰 | 协作、Power-Ups、自动化膨胀 |

### 7.3 跨窗口通信约定

- 事件命名:`<namespace>:<verb>:<entity>`,如 `grid:created`, `clipboard:item_added`
- 事件 payload 强类型:在 `packages/core-events/` 维护 TypeScript types,Rust 侧用 `serde` mirror
- 不允许跨 Plugin 直接 import — 必须走 events

### 9.2 双轨技术实现要点

**架构层面**(Phase 0 就要做对的事):
1. **`macOSPrivateApi: false`** — 用基础透明(setBackgroundColor: clearColor + opaque: false)替代 Tauri 私有 API 路径
2. **Cargo features 分离两个 target**:
   ```toml
   [features]
   default = ["full"]
   full = []        # DMG 版,所有能力
   sandbox = []     # MAS 版,沙箱兼容路径
   ```
3. **文件访问统一走 abstraction**:`packages/core-fs/` 提供 `openPath()` API,完整版直接走 `std::fs`,沙箱版走 security-scoped bookmarks
4. **剪贴板从一开始就考虑沙箱**:NSPasteboard API 本身在沙箱可用,只是 source app 元数据要 fallback
5. **不写死 macOSPrivateApi 依赖的视觉效果**

**Entitlements 清单(MAS 版,Phase 0 末完成 entitlements.plist)**:
- `com.apple.security.app-sandbox` = true
- `com.apple.security.files.user-selected.read-write` — 拖入/选择的文件
- `com.apple.security.files.bookmarks.app-scope` — 持久访问已授权文件
- `com.apple.security.files.downloads.read-write` — Downloads 读写(可选)
- `com.apple.security.network.client` — 账号 + 同步
- `com.apple.security.automation.apple-events` + 具体 receiver(若需要)— 暂不需要
- 不需要 `com.apple.security.cs.disable-library-validation` 等"危险"项

**Phase 0 多增加的工作量**:1~1.5 周(主要在文件访问抽象 + entitlements + 双 target 打包脚本)。

### 10.4 Phase 0 "地基重建" 详细拆解

Phase 0 拆为 3 个串行子阶段,**M0-A 是 go/no-go gate**——spike 不通过就不允许进入子阶段 2。

**子阶段 0.1 · 技术 Spike(1.5-2 周)— go/no-go gate**

目标:在真机上验证三大核心问题是否有干净的解,**不写产品功能**,只做最小验证原型。

| 验证项 | 当前症状 | spike 要回答的问题 |
|---|---|---|
| 桌面点击穿透 | 根本点不动桌面图标 | 主窗口该不该存在?能否做到"Grid 窗口可交互 + 桌面空白区可穿透"?主窗口若保留是否必须永远 `setIgnoreCursorEvents(true)`? |
| 文件拖入 | 完全没反应 | Tauri 2.9 的原生 `onDragDropEvent` 在**非透明的 Grid 窗口**上是否可用?(透明限制只针对主 overlay,Grid 是实心面板)能否拿到真实路径? |
| 多 Space / 全屏 | 行为奇怪 | `collectionBehavior` 各组合在真机上的实际表现?per-window 设置 vs 全局? |
| 多 Grid 窗口干扰 | 互相干扰 | 跨窗口事件是否需要按 gridId scope?窗口生命周期管理 |

产出:`docs/adr/0001-window-architecture.md`(架构决策记录)+ 最终窗口模型定论。

**子阶段 0.2 · 原生层重建(3-4 周)**

按 spike 结论重写:
- `apps/desktop/src-tauri/src/lib.rs` — 窗口管理彻底重写,清掉未完成的 pivot 残留
- `apps/desktop/src/hooks/useGlobalMouse.ts` — 点击穿透模型重做(移除 `// TEMPORARY` 硬编码)
- `packages/plugin-organizer/src/hooks/useFileDrop.ts` — 改用 Tauri 原生拖放,拿真实路径

### 10.5 一个必须正视的风险

**如果子阶段 0.1 的 spike 结论是"透明桌面 overlay 在 Tauri 上没有干净解"** —— 那整个产品形态都要重新考虑。备选:(a) 放弃全屏 overlay,纯多窗口(Grid 窗口 + Control 窗口作为离散窗口,不覆盖桌面);(b) 改用 macOS Widget Extension(需大量原生开发,Tauri 不直接支持);(c) 接受"模式切换"折中(快捷键激活/退出 overlay 模式)。这就是为什么 M0-A 设为 go/no-go gate——**早死早超生,不要在坏地基上盖 6 个月的楼。**
