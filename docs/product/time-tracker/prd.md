## Purpose and bounds

Users can track category work as paused/running sessions, choose single or multiple concurrent tasks, and view/report time without replacing the original session records. This canonical PRD records the **accepted mode/session capability slice** required by TT08, with source and historical evidence. It does not complete the full Time Tracker PRD backlog or GOV05's wider dossier requirement.

## Actual page and dashboard relationship

The module already shows the EN/ZH mode selector, single Start confirmation and mounted-page controller error/original-source export controls. TT08 page synchronization is checked against that actual source, with zero page/source edit needed. It does not claim new browser interaction, visual, keyboard, mobile or accessibility acceptance.

The [Time Tracker widget](../../../packages/xai-web-dashboard-widgets/src/widgets/TimeTrackerWidget.tsx) uses `getTimeTrackerSnapshot(now)` to display totals/runningCount/top category and opens `timetrack`. It does not read mode directly or offer Start/Pause/End controls. Insights/CSV consume entry/window helpers. Public [index.ts](../../../packages/plugin-web-time-tracker/src/index.ts) exports mode type/key, module and snapshot, while mode read/write/hook and entry controller functions remain internal. No new widget or public command API is required by this PRD slice.

## Observed implementation limits and unconfirmed scope

**Mode conversion is an observation, not an owner-approved migration rule.** `writeTimeTrackerMode` changes only `xai_tt_mode` and emits an event. Selecting Single after Multi can leave multiple existing running sessions because the entry controller rejects newly running IDs rather than reconciling unchanged existing IDs. A later confirmed Single Start ends the then-running set. Immediate choose/end/reconcile on mode selection would require a separate owner decision and product implementation path; this documentation does not invent one.

The mode key is an unscoped device preference, while categories/entries use account/generation physical keys. Mode writes are outside the entry Web Lock transaction and do not inherit its storage-error/recovery guarantees. Original-byte export and mounted draft retention are bounded capabilities, not full restore/import/reload recovery.

DASH07 widget controls, TT04 category-deletion transaction safety, TT05–07 remaining work including TT07 performance/scaling, REL04, GOV04 status calibration and the full GOV05 dossier remain separate. Category CRUD and the broader existing package surface are not newly accepted by this mode/session slice. Cloud sync, account-wide isolation, quota, disposal, all historic timezone offsets, offline/online, real/dual-device, RLS, credentials/signing/payment and production/release gates are not established here.
